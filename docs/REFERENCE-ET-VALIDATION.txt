3. CODE SOURCE

https://github.com/sintaxerrorpvtltd/Open-Tangerine
Commit analysé : a1ff18575c5000cc50373e851e2bbe7a2b919245.
Mac Swift0.1.10 et Desktop Python0.2.1 sont des implémentations distinctes.
Le Desktop upstream est plus limité et n’a pas la roue globale ni le panneau
Mac. Les données de style viennent du Swift, pas des GIF illustratifs du README.
La correspondance binaire/source n’est pas prouvée par un build reproductible.

Repris/adapté : rayons64/150, espace4, arrondis tangents, capsule centrale120x34,
accent#FF5C00 ; ouverture de0,84 vers1 ; survol1,025 et déplacement4px ; menus
convertir/outils/actions ; panneau centré en haut, résultats glissables ; mascotte
vectorielle avec états ; thème clair/sombre, réduction des mouvements et tray.

Remplacements : SwiftUI/AppKit -> Qt/Win32 ; ImageIO/CoreImage -> Pillow/HEIF ;
PDFKit -> PyMuPDF/pdf2docx ; AVFoundation -> FFmpeg ; Office -> LibreOffice/Pandoc.
La roue Qt conserve ses propres événements et sa pagination. L’interpolation
OutBack approche le ressort ; elle n’est pas une reproduction physique exacte.

4. VÉRIFICATION

Moteur : 88 tests réussis dans engine-final.xml, plus 1 test d’annulation réelle
d’un processus et de son enfant dans cancellation.xml. Couverture : formats
photo/audio/vidéo, PDF/Office, sous-titres, archives, collisions, traversée de
chemins, annulation, lot partiellement invalide, intégrité des originaux.
Les Office vérifient de vrais PDF/DOCX/ODT, pas seulement un fichier non vide.

Outils complémentaires : 33 tests réussis. Vérification de pixels masqués avant,
pendant et après l’intervalle vidéo, audio du visualiseur, champs EXIF/PDF relus,
pixels JPEG préservés, empreinte SHA256 exacte, duplication et collisions.

Interface : 6 tests Qt réussis, processus terminé avec code0 après nettoyage
des fenêtres. Dépôt/selecteur, clavier/pagination, édition visuelle, file et
historique d’erreur/succès, options UI réellement envoyées aux moteurs.
Un avertissement de dépréciation du constructeur QDragEnterEvent dans le test
reste présent ; il n’affecte pas le programme livré.
Tab et Échap sont routés vers la roue flottante même quand l’atelier garde le
focus ; les tests vérifient les deux fenêtres et un seul changement par appui.

Essai Windows réel : fenêtre ouverte, PNG de démonstration déposé dans la roue,
secteur JPG puis dépôt/clic ; résultat JPG et historique de réussite constatés.
La commande F8 affiche une roue flottante transparente. Aucun document personnel
n’a servi aux conversions de test. Le geste Maj maintenu pendant un glissement
depuis une autre fenêtre Explorer n’est pas certifié par cet essai.
La dernière compilation Zeste.exe a aussi été ouverte dans Windows : F8 affiche
la roue, Tab passe de Convertir à Outils en un appui et Échap la ferme. Ces
trois actions ont été observées dans la fenêtre réelle du portable final.

Le volet de partage a été compilé et son mode --check exécuté ; aucun envoi à
une application ou un destinataire tiers n’a été effectué.

Les résultats de vérification du portable sont dans tests/artifacts et dans
le rapport livré avec la distribution ; ils sont distincts des tests source.
Les neuf scénarios du portable utilisent un PATH limité à System32 et des
profils isolés : démarrage réel avec code0, identité des sources/inventaire,
JPG/HEIC, DOCX vers PDF avec LibreOffice privé, PDF vers DOCX, Markdown vers EPUB
avec Pandoc privé, audio vers MP3 avec FFmpeg privé, archive7z et réextraction.
Les sources et SHA-256 de construction sont inscrits dans .zeste-generated.json.

5. DIFFÉRENCES RESTANTES

Pas d’API Apple ni Liquid Glass natif ; roue globale limitée à Explorer/Bureau ;
pas d’éditeur vidéo avec timeline, ni de PDF réorganisé par vignettes ; champs
numériques à la place. Les fonctions OCR/IA/Pages/AirDrop ne sont pas fournies.
Sortie PowerPoint à partir d’un PDF en images, Excel sur tableaux détectables,
compression à taille indicative, formats/codages réels soumis aux moteurs.
Ces limites sont aussi indiquées dans README.txt et dans les dialogues concernés.
